# LoRa NLOS: Transmitter + Receiver (ESP32 + Ra-01H)

Система з двох вузлів для дослідження радіоканалу LoRa в умовах без прямої видимості (NLOS):

| Вузол | Файл | Роль |
|---|---|---|
| **A, Mobile** | `Transmitter.ino` | Шле пакети, у режимі ACK чекає підтвердження. Пише лог у флеш. |
| **B, Base** | `Receiver.ino` | Приймає пакети, міряє RSSI / SNR / PDR **прямого каналу**, відповідає ACK. |
| ПК | `serial-mon.py` | Термінал для команд і автоматичне збереження дампа CSV у файл. |

Головні дані для графіків збирає **приймач**. Лог передавача доповнює їх: PDR туди-назад, RSSI/SNR зворотного каналу, час туди-назад (RTT).

---

## 1. Підключення

### Ra-01H (SX1276), обидва вузли

| Ra-01H | ESP32 DevKit |
|---|---|
| 3.3V | 3V3 |
| GND (усі три) | GND |
| NSS | D27 |
| MOSI | D23 |
| MISO | D19 |
| SCK | D18 |
| RESET | D14 |
| DIO0 | D26 |
| ANT | пружинна антена, другий кінець вільний |

- Живлення **тільки 3.3 В**, не 5 В / VIN.
- Біля модуля: конденсатори 100 нФ і 10 мкФ паралельно між 3.3V і GND.
- **Не вмикати модуль без антени.**
- DIO1–DIO5 не підключені, прошивкам вони не потрібні.

### Ra-01SH (SX1262), комплект організаторів, тільки для приймача

Інший чіп, тому одних пінів мало. У `Receiver.ino`:
1. закоментувати `#define MODULE_RA01H`, розкоментувати `#define MODULE_RA01SH`;
2. вписати піни shield-а: **NSS, RST, DIO1 (переривання), BUSY**. Піни в коді зараз умовні;
3. якщо при старті помилка `-706` або `-707`, змінити `TCXO_V` (`0.0` ↔ `1.8`).

## 2. Встановлення

1. **Arduino IDE** → File → Preferences → Additional boards manager URLs:
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
2. Tools → Board → Boards Manager → `esp32` (Espressif Systems) → Install.
3. Sketch → Include Library → Manage Libraries → **RadioLib** (автор Jan Gromeš) → Install.
4. Плата: **ESP32 Dev Module**, порт: COM-порт плати (потрібен драйвер CP2102).
5. Для Python-скрипта: `pip install pyserial`.

Якщо прошивка зависає на `Connecting...`, затисніть кнопку **BOOT** на платі.

---

## 3. Перший запуск (на столі)

1. Прошити `Transmitter.ino` на вузол A, `Receiver.ino` на вузол B.
2. **Закрити Arduino Serial Monitor**, інакше порт зайнятий.
3. Відкрити два термінали, у кожному `python serial-mon.py`, ввести порти плат.
4. **Тільки при першому запуску** на обох платах: `format YES`.
5. Перевірити `status` на обох: має бути `radio=OK` і `fs=OK`.
6. Плати на відстані 1–2 м, мала потужність, щоб не перевантажити приймач:
   - приймач: `preset 1`, потім `power 5`
   - передавач: `config 1 1 1 1 10 8000 5`, потім `start`
7. На приймачі мають йти рядки `RX` і `ACK_TX`, на передавачі `ACK_RX`.
   Наприкінці приймач друкує `# SUMMARY ...`, передавач `# DONE ... Final PDR`.

> Відкриття порту з Python **перезавантажує ESP32**. Флеш і налаштування зберігаються, але статистика приймача в пам'яті обнуляється. Тому спершу підключайте скрипти, а потім робіть `start`.

## 4. Команди передавача (`Transmitter.ino`)

| Команда | Що робить |
|---|---|
| `help` або `?` | Список команд |
| `status` | Стан радіо, флешу, поточна конфігурація, ToA і мінімальний інтервал |
| `table` | Усі пресети з ToA і мінімальним інтервалом |
| `config RUN POINT PRESET MODE COUNT INTERVAL_MS POWER_DBM` | Нова конфігурація, зберігається в NVS |
| `start` | Старт через 5 с |
| `stop` | Перервати прогін |
| `reset` | Обнулити лічильники (CSV не чіпає) |
| `dump` | Вивести `/measurements.csv` (скрипт збереже у файл) |
| `erase YES` | Видалити `/measurements.csv` |
| `format YES` | Форматувати флеш (лише перший запуск або збій) |

### Параметри `config`

| Параметр | Значення |
|---|---|
| `RUN` | ID прогону. **Кожен `start` потребує нового RUN**, повтор відхиляється. |
| `POINT` | Номер точки вимірювання |
| `PRESET` | 1–5, див. таблицю нижче |
| `MODE` | `0` = тільки передача, `1` = з ACK |
| `COUNT` | Кількість пакетів (1–10000) |
| `INTERVAL_MS` | Інтервал між пакетами, мс |
| `POWER_DBM` | Потужність, 2–17 дБм |

Приклад: `config 1003 3 2 1 20 26000 14`, тобто прогін 1003, точка 3, SF9, з ACK, 20 пакетів, кожні 26 с, 14 дБм.

## 5. Команди приймача (`Receiver.ino`)

| Команда | Що робить |
|---|---|
| `help` або `?` | Список команд |
| `status` | Стан радіо, флешу, пресет, потужність ACK |
| `preset N` | Пресет 1–5. **Має збігатися з передавачем.** |
| `power DBM` | Потужність ACK, 2–17 дБм |
| `summary` | Підсумок поточного прогону: PDR, середні RSSI і SNR, дублікати, помилки CRC |
| `reset` | Обнулити статистику |
| `table` | Пресети з ToA |
| `dump` | Вивести `/rx.csv` |
| `erase YES` | Видалити `/rx.csv` |
| `format YES` | Форматувати флеш |

Приймач сам розпізнає новий прогін за RUN ID і обнуляє статистику. ACK шле тільки коли передавач у `MODE 1`. Якщо пресет пакета не збігається з пресетом приймача, з'являється `#WARN`.

## 6. Пресети

| Пресет | SF | BW, кГц | CR | ToA (32 байти), мс | Мін. інтервал для 1% duty cycle |
|---|---|---|---|---|---|
| 1 | 7 | 125 | 4/5 | 72 | ~7,7 с |
| 2 | 9 | 125 | 4/5 | 247 | ~25 с |
| 3 | 12 | 125 | 4/5 | 1810 | ~182 с |
| 4 | 7 | 250 | 4/5 | 36 | ~4,1 с |
| 5 | 7 | 125 | 4/8 | 103 | ~10,8 с |

Частота 868,1 МГц, sync word 0x12, преамбула 8, CRC увімкнено. Прошивка інтервал не контролює: дотримання 1% duty cycle на вашій відповідальності.

## 7. Формат CSV

### Передавач, `/measurements.csv` (node = `A`)

`schema,node,boot_id,event,run_id,point_id,preset,mode,seq,t_ms,freq_hz,sf,bw_hz,cr_den,tx_power_dbm,packet_bytes,planned_count,interval_ms,toa_ms,rssi_dbm,snr_db,pdr_pct,ack_count`

Події: `START`, `TX_ATTEMPT`, `TX_DONE`, `ACK_RX`, `ACK_TIMEOUT`, `TX_UNCERTAIN`, `TX_FAIL`, `END`, `STOP`.
- `rssi_dbm`, `snr_db` є лише в `ACK_RX`, це **зворотний** канал.
- `pdr_pct` це PDR туди-назад (пакет дійшов **і** ACK повернувся).
- **RTT** = `t_ms(ACK_RX) − t_ms(TX_ATTEMPT)` для одного `seq` (трохи завищений через запис у флеш і паузу ACK 200 мс).

### Приймач, `/rx.csv` (node = `B`)

`schema,node,boot_id,event,run_id,point_id,preset,mode,seq,t_ms,freq_hz,sf,bw_hz,cr_den,tx_power_dbm,packet_bytes,planned_count,toa_ms,rssi_dbm,snr_db,rx_unique,pdr_pct,acks_sent`

Події: `RUN_START`, `RX`, `RX_DUP`, `ACK_TX`, `ACK_FAIL`.
- `rssi_dbm`, `snr_db` у рядках `RX` описують **прямий** канал. Це головні дані.
- `pdr_pct` = унікальні прийняті / найбільший номер пакета, що мав прийти. Фінальний PDR щодо запланованої кількості є в `# SUMMARY`.

Дампи обох вузлів зберігаються як `measurements_dump_<час>.csv`. Розрізняйте їх за колонкою `node` і одразу перейменовуйте (`point3_rx.csv`).

## 8. Методика NLOS

Мета: показати, **як перешкоди погіршують зв'язок і яка конфігурація це витримує**.

1. **Опорна точка LOS.** Один вимір у прямій видимості на 20–50 м. Без неї нема з чим порівнювати втрати в NLOS.
2. **Точки NLOS за типом перешкоди**, а не лише за відстанню:
   - одна стіна (сусідня кімната);
   - кілька стін / інший поверх;
   - будівля між вузлами (за рогом, через корпус);
   - кілька будівель / підвал (найгірший випадок).

   Для кожної точки записати номер `POINT`, відстань (GPS або карта), тип перешкоди, фото.
3. **Однакові умови в кожній точці:** антени вертикально, на однаковій висоті, вузол не в руці і не біля тіла (тіло дає 5–10 дБ втрат), однакова потужність.
4. **Шукати межу зв'язку.** Найцінніший результат: точка, де SF7 уже не працює (PDR близько 0), а SF12 ще тримає. Це і є trade-off дальності та швидкості.
5. **Наживо бачити, чи є зв'язок.** У NLOS той, хто несе мобільний вузол, цього не бачить. Варіант: `MODE 1` і телефон із застосунком на кшталт Serial USB Terminal (Android, OTG-кабель), підключений до передавача. `ACK_RX` означає «є зв'язок», `ACK_TIMEOUT` означає «точка мертва».

### Порядок у кожній точці

1. Приймач біля ноутбука, нерухомо, весь час на одному місці.
2. Для кожного пресету: `preset N` на приймачі → `config <новий RUN> <POINT> N 1 <COUNT> <INTERVAL> 14` на передавачі → `start` → дочекатися `# SUMMARY`.
3. Після точки зробити `dump` на приймачі й перейменувати файл.

### Бюджет часу

Реалістично: 4–5 точок × 3 пресети (SF7, SF9, SF12, усі BW125) × 20 пакетів. SF12 з дотриманням 1% duty cycle займає ~3 хв на пакет, тож для нього брати 10 пакетів або **чесно вказати в презентації**, що інтервал скорочено.

### Графіки для захисту

- RSSI і SNR по точках, окрема лінія на кожен пресет.
- PDR по точках для кожного пресету.
- Розрахований ToA проти виміряного RTT по пресетах.
- Підсумкова таблиця: який пресет для якого сценарію (телеметрія, команди, межа зв'язку).

## 9. Проблеми та рішення

| Симптом | Причина / рішення |
|---|---|
| `#ERROR radio init, code -2` | Модуль не відповідає по SPI: пайка, NSS, живлення 3.3 В, MISO/MOSI переплутані |
| `#ERROR radio init` на Ra-01SH, `-706` / `-707` | Змінити `TCXO_V`, перевірити BUSY |
| `fs=FAIL` | Виконати `format YES` |
| `#ERROR choose a NEW run ID` | Збільшити RUN у `config` |
| Приймач нічого не чує | Різні пресети на вузлах; немає антени; передавач не в `start` |
| Тільки `ACK_TIMEOUT` на передавачі | Приймач не в тому пресеті або ACK не долітає (слабкий зворотний канал) |
| Скрипт не відкриває порт | Закрити Arduino Serial Monitor або інший термінал |
| Статистика приймача обнулилась | Порт перевідкрили, і плата перезавантажилась |

## 10. Обмеження

- Прошивки перевірено за вихідним кодом RadioLib 7.8.1 і окремим тестом сумісності пакетів на ПК, але **не скомпільовано під ESP32**. Можливі дрібні помилки збирання.
- Піни для Ra-01SH умовні, їх треба взяти з плати організаторів.
- У протоколі немає службового каналу, тому пресет на обох вузлах виставляється вручну.
